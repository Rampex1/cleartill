# Cleartill

Stripe-style payments API (learning clone). Design: `research/design/stripe-clone.md` (local, git-excluded).

- `api/`: FastAPI + SQLAlchemy 2 + Alembic + Postgres (Python 3.13, uv).
- Tests (needs Docker running; testcontainers starts Postgres 16): `cd api && uv run pytest -q`
- Lint: `cd api && uv run ruff check . && uv run ruff format --check .`
- Run locally: `docker compose up -d --build` → `curl localhost:8000/healthz`
- New migration: `cd api && uv run alembic revision -m "..."` (hand-written SQL is fine).
- Tests use a per-test outer transaction with `join_transaction_mode="create_savepoint"`: a `commit()` in code under test only releases a savepoint.
- `app.db` reads `DATABASE_URL` at import; tests get it from `pytest_configure` in `tests/conftest.py`, so top-level `from app.main import app` in test modules is fine.
- API conventions live in `api/app/`: `forms.params` (Stripe form bodies → dict; array fields use `forms.FormList[T]`), `errors.ApiError` (Stripe error envelope), `auth.require_secret_key`/`require_publishable_key`, `ids.new_id(prefix)`, `clock.now()` (monkeypatch in tests), `urls.validate_redirect_url`.
- Never put submitted values into error messages or logs (validation messages use our own wording per Pydantic error type; the engine has `hide_parameters=True`).
- `app/tenancy.py`: load every object with `get_owned(db, Model, id, merchant_id, param=…)` (404 for other tenants; `for_update=True` for writes) and list with `paginate`. Validate client params with `forms.validate(Model, params)` (never `Model.model_validate` on client input).
- `app/executor.py`: every `/v1` write route returns `execute(db, request, auth.merchant.id, params, handler)`; the handler returns a dict or `Result(status, body)` and raises `ApiError` for 4xx. Handlers never call `db.commit()`. FastAPI dependencies (auth etc.) must only read: their writes would sit outside the executor's savepoint. `Idempotency-Key` (POST only) is handled there.
- Dashboard auth: session cookie `cleartill_session` (HttpOnly, Secure, SameSite=Lax, 7 days) also authenticates `/v1`; cookie-authenticated writes need `X-Cleartill-Dashboard: 1`. `/dashboard-api` uses `require_session` (cookie only). Tests with cookies need `TestClient(app, base_url="https://testserver")`. Login/signup are rate-limited per `ratelimit.client_ip` (`TRUSTED_PROXY_HOPS`, default 0 = ignore X-Forwarded-For).
- Ledger (`app/ledger.py`): `post()` is the only journal writer (one multi-row INSERT). Postgres triggers reject unbalanced/single-leg/multi-currency/appended transactions and any UPDATE/DELETE of journal rows, so committed-data tests leave their (consistent) ledger rows behind; merchants with balance transactions can't be deleted. Prefer the savepoint `db` fixture. Money tests should end with `assert ledger_check(db, own_txn=False) == []`.
- Events (`app/events.py`): every state change calls `emit(db, merchant_id, event_type, obj_json, request)` inside the executor handler (request=None for worker/automatic events) (same transaction), so rollbacks and idempotent replays emit nothing.
- Cards (`app/cards.py`): card numbers/CVCs exist only in memory during `tokenize`; store brand/last4/expiry/fingerprint/sim_outcome only, and never put any part of a number in an error, log or response. `POST /v1/payment_methods` is publishable-key only. `SECRET_KEY` (fingerprint HMAC) is required; tests set it in `pytest_configure`.
- `SECRET_KEY` (≥32 chars, checked at startup) is the root of derived keys (`config.keyed_hash(purpose, msg)`). Routes that take card data pass a redacted `hash_params` to `execute` and pk routes use `key_scope="pk:"`.
- Amounts: parse with `forms.FormInt` (ASCII digits only) and check bounds with `forms.require_amount(value, minimum=…)` (codes amount_too_small/amount_too_large). Create PIs through `payment_intents.create_pi` (emits payment_intent.created).
- `PUBLIC_BASE_URL` (checked at startup via `config.public_base_url()`; tests use https://testserver) builds absolute URLs. Confirm logic lives in `payment_intents.confirm_pi`, with `approve()` / `decline()` reusable by 3DS (M16) and checkout (M17).
- Webhook worker: `python -m app.worker` loops `delivery.deliver_one()` (claim with fencing → `send` outside any transaction, pinned to vetted IPs → fenced `finish` with an attempt row). Signatures: `webhooks.sign` / `webhooks.verify` (`Cleartill-Signature`).
- Worker housekeeping (`app/housekeeping.py`, every 60 s from `worker.tick`): release due funds, 7-day auth expiry, idempotency-key purge, expired dashboard sessions; `ledger_check` on start. `docker compose up` runs the worker too (dev compose sets ALLOW_INSECURE_URLS=1 so webhooks can target `host.docker.internal`).
- Hosted-page endpoints live in `app/routers/checkout.py` (`/checkout-api`, no API key; the PI client_secret is the credential, compared with `hmac.compare_digest`, unknown id and wrong secret give the same 404). 3DS: `POST /checkout-api/3ds/{pi}` with result=approve|fail reuses `approve()`/`decline()`.
- Checkout (`app/checkout.py`, `/v1/checkout/sessions`, `/checkout-api/sessions/{cs}[/pay]`): one eager PI per session; checkout PIs reject /v1 update/confirm/cancel (`require_not_checkout`); `/pay` and 3DS lock the session before the PI and call `complete_if_paid`; `expire_sessions` runs from `worker.tick`. `cards.save` persists a tokenized card.
- Web SPA in `web/` (Vite + React Router, JSX): `npm ci && npm run build` → `web/dist`, served by `app.frontend()` only when built (`WEB_DIST`). Every response has the CSP and Referrer-Policy (`app/frontend.py`); no inline scripts or styles. E2E: `cd api && uv run playwright install chromium && uv run pytest -q tests/e2e` (needs web/dist; e2e tests run last). The Docker build context is the repo root (`api/Dockerfile`, root `.dockerignore`).
- Dashboard pages in `web/src/dashboard/` (cookie auth; `dash.js` adds `X-Cleartill-Dashboard: 1` to POSTs; `useIdempotencyKey()` gives one key per rendered action, renewed after each response). Dashboard e2e uses `http://localhost:<port>` (Secure cookie).
